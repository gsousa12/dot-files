# feat — guia para agentes

Read this before changing anything about `feat`, its profiles, or its Zed integration. User-facing docs (Portuguese): [`__info.md`](./__info.md) (install/config) and [`GUIA.md`](./GUIA.md) (how to use); keep them in sync when behavior changes. User-visible strings in the script are Portuguese — keep that.

## Pieces and where they live (all in the dotfiles repo `~/Pessoal/dot-files`)

| Repo path | Installed as (symlink) | Role |
|---|---|---|
| `.local/bin/feat` | `~/.local/bin/feat` | The whole tool. One bash script, `set -euo pipefail`. |
| `.config/feat/` | `~/.config/feat` | `default-profile`, one dir per profile, `install.sh`, docs. |
| `.config/shell/feat.zsh` | `~/.config/shell/feat.zsh` | zsh completion (`_feat`) and `fcd`; sourced by `zsh/.zshrc`. |
| `.config/zed/tasks.json`, `keymap.json` | copied to `~/.config/zed/` | Tasks labelled `feat: …`; keys `alt-shift-f` (menu), `alt-shift-n/u/d`. Check Zed's default keymap (`assets/keymaps/default-linux.json`) before binding a key — `ctrl-alt-f` was taken by `text_finder::Toggle`. Zed files are **copied**, not linked: after editing, copy to `~/.config/zed/` (back up first, as `<file>.backup-YYYYMMDD-HHMMSS`). |

Outside git on purpose: `~/.local/share/feat/<profile>/env/<repo>/` (`.env` templates with secrets), `~/.local/state/feat/running` (runtime state). `mprocs` 0.9.6 lives in `~/.local/bin/mprocs` (installed by `install.sh --mprocs`; 0.10+ was renamed *dekit* and changed config format — do not upgrade without porting `write_mprocs`).

## Data model

- **Profile** = one project/employer. `project.conf` is sourced bash (variables only; defaults are set in `load_profile`). `repos.conf` is `repo | base | run` per line, exceptions only; `-` = auto, run `none` = never started.
- **Repo index** = every dir under `REPOS_ROOT` (depth ≤ `SCAN_DEPTH`) containing a `.git` *directory*, keyed by basename. Linked worktrees have a `.git` *file* and are excluded. Basenames must be unique.
- **Feature** = `$FEATURES_DIR/<NAME>/` with `.feat/feature.conf` (`NAME`, `BRANCH`, `PROFILE`, written with `printf %q`, sourced back) and `.feat/repos` (`name|main-repo-path|base` per line). Each `<NAME>/<repo>/` is a git worktree of the main repo. `.feat/mprocs.yaml` is regenerated by `write_mprocs` — never hand-edit it.
- Any command run inside a feature dir finds it by walking up to `.feat/feature.conf` (`find_feature_dir`), so Zed tasks only need `cwd: $ZED_WORKTREE_ROOT`.

## Behavior contracts (keep these when editing)

- Branch resolution in `add_repo`: checked out in another worktree → refuse unless `--move` (then `git worktree move`); local branch → use; `origin/<branch>` → track it; else create from `origin/<base>` with `--no-track`.
- Never overwrite an existing file when copying env; template dir first, then main repo `.env*` minus `*.example|*.sample|*.template`.
- Dependencies install in parallel, only where `node_modules` is missing; logs in `.feat/logs/install-<repo>.log`.
- Services: mprocs runs `feat _run <worktree>` per repo, so the command is resolved at runtime (`run_cmd`) and `.nvmrc` is honored. Only one feature runs at a time: `feat up` records `<NAME> <pid>` and `exec`s mprocs; `stop_running` kills that pid plus all descendants (never by cwd — Zed's language servers live in the same dirs).
- `feat rm` refuses on dirty worktrees or unpushed commits unless `--force`; branch deletion only with `--delete-branch` and uses `git branch -d` (safe).
- Functions that end in a loop or `&&` list must `return 0` explicitly — `set -e` + a false last status makes callers treat them as failures.

## Common customizations

- New repo exception → add a line to `<profile>/repos.conf`.
- New project → copy a profile dir, edit `project.conf`, change `default-profile`.
- New subcommand → add `cmd_<name>`, list it in `main`'s `case`, in `cmd_help`, in `_feat` (feat.zsh), in `cmd_menu`, and optionally a Zed task + keybinding.
- Different editor → `OPEN_CMD` in `project.conf`.

## Testing changes

Never test against the real repos. Build a sandbox: bare repos as `origin`, clones under a fake `REPOS_ROOT`, and run with `FEAT_CONFIG_DIR=<sandbox cfg> XDG_STATE_HOME=<sandbox state>` and `OPEN_CMD="true"`. Run `bash -n .local/bin/feat` (and `shellcheck` if available).
